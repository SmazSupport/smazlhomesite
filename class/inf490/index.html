Stevens Networking Solution

Network Client Inventory & Interface Monitoring Tool

Fall 2026 Sole Developer In Progress

The Problem

A hotel management company remotely operates the network at a branded hotel property in Houston, TX — roughly 15–20 computers, several access points, and multiple VLANs (Staff, PMS, Guest, IoT) running on Cisco Meraki cloud-managed equipment. The company's network shares infrastructure with the property's guest Wi-Fi, creating a boundary between two networks.

Today the IT team has no centralized view of what's connected to the network, where devices are plugged in, or what's changed. Hotel environments mean guests and contractors are constantly connecting equipment, but there's no rogue device detection, no change history for "what changed?" troubleshooting, and no visibility into traffic crossing the boundary to the property's guest network. Everything is manual digging through the Meraki dashboard.

The Solution

A custom monitoring tool that pulls client, device, interface, and VLAN data from the Cisco Meraki Dashboard API into a Python backend and SQL database, then surfaces it in a purpose-built web dashboard.

Key Features

  • 📋 Live device inventory — every client on the network in one searchable view
  • 🔌 Switch port and MAC address tracking with OUI manufacturer lookup
  • 🚨 Rogue device detection — automatic flagging of unknown devices
  • 🗂️ VLAN visibility across Staff, PMS, Guest, and IoT networks
  • ⬌ Cross-boundary monitoring between the client network and the property's guest Wi-Fi
  • 🔔 Automated alerts for rogue devices, offline events, bandwidth spikes, and boundary anomalies
  • 📝 Change history log for "what changed?" troubleshooting

My Role

Sole developer and project owner — every phase of this project is mine, working directly with the client's IT/network manager.

Discovery & requirements

Working directly with the client to understand the network environment and what information is actually useful to the IT team.

Architecture & build

Designing and building the full stack — Meraki API integration, Python backend, database schema, and web dashboard.

Testing & documentation

Validating detection logic and data accuracy against the real network, and documenting the system for client handoff.

Client communication

Scope management, proposal, MOU, progress updates, and deliverable review — the full client relationship.

Planned Outcomes

This project is in progress — the goal is a single place to see the network:

Goals

  • 🎯 A real-time device inventory that replaces manual Meraki dashboard lookups
  • 🎯 Automatic identification of unknown devices and issues instead of manual discovery
  • 🎯 A change history that answers "what changed?" during troubleshooting
  • 🎯 Visibility into traffic and devices crossing the boundary to the property's guest network
  • 🎯 An always-current network baseline the IT team can rely on
